🌐1. What is a Computer Network?

A computer network is a collection of devices connected together so that they can communicate and share resources.

Laptop ─────┐ Desktop ────┤ Printer ────┤ │ SWITCH │ ROUTER │ INTERNET

Devices communicate using networking protocols — agreed-upon rules for how data is sent and received.

Network Devices

💻
Computer / Laptop
End-user device that generates and consumes data
📼
Server
Provides services (web, file, email) to other devices
🖨
Printer
Shared resource on the network
🔌
Switch
Connects devices within a LAN using MAC addresses
📡
Router
Connects different IP networks using IP addresses
🔒
Firewall
Controls traffic based on security rules
📶
Wireless AP
Provides Wi-Fi connectivity to wireless devices
📱
Modem
Converts signals between ISP and your network

🔌2. Switch

A switch connects devices within the same Local Area Network (LAN). It uses MAC addresses to forward Ethernet frames only to the correct destination port — unlike a hub which broadcasts to all ports.

PC1 ──┐ PC2 ──┤ PC3 ──┤── Switch Printer ┘
💡
How it works: If PC1 wants to talk to PC2:
PC1 → Switch → PC2
The switch reads PC2's MAC address and sends the frame only to that port. All other ports are silent.
📌
OSI Layer: Switch operates at Layer 2 (Data Link) and uses MAC addresses.

📡3. Router

A router connects different IP networks. It makes forwarding decisions using IP addresses and routing tables.

Network A 192.168.1.0/24 │ Router │ Network B 192.168.2.0/24
🎓
Key distinction for interviews:
🔌 Switch → connects devices within the same network (Layer 2, MAC)
📡 Router → connects different IP networks (Layer 3, IP)

🔒4. Firewall

A firewall controls network traffic according to security rules. It sits between the internet and your internal network.

Internet │ ▼ Firewall │ ▼ Internal Network

A firewall can filter traffic based on:

  • Source IP — where traffic is coming from
  • Destination IP — where it's going
  • Port — which service (80=HTTP, 443=HTTPS)
  • Protocol — TCP, UDP, ICMP
  • Application — (advanced/Next-Gen firewalls)
Example rules: Allow TCP 443 → HTTPS traffic allowed Deny TCP 23 → Telnet blocked (insecure)
📌
Firewalls will be studied much more deeply in Month 2. For now, understand what they do and why they exist.

📶5. Wireless Access Point (AP)

An Access Point provides wireless connectivity to devices and connects them to the wired network.

Switch │ AP / | \ Laptop Phone Tablet
💡
You've worked with APs in IT support. Architecturally, the AP bridges wireless clients to the wired LAN — it's not a router. The router is upstream.

📚6. The OSI Model — 7 Layers

The Open Systems Interconnection (OSI) model is a conceptual framework used to understand how network communication works. It has 7 layers.

Layer 7 → Application Layer 6 → Presentation Layer 5 → Session Layer 4 → Transport Layer 3 → Network Layer 2 → Data Link Layer 1 → Physical
🧠
Memory trick (Layer 1 → 7, bottom up):
"Please Do Not Throw Sausage Pizza Away"
Physical → Data Link → Network → Transport → Session → Presentation → Application
LayerNameData UnitImportant Concepts
7ApplicationDataHTTP, HTTPS, DNS, SSH, SMTP, FTP
6PresentationDataFormatting, Encoding, Encryption, Compression
5SessionDataSession management (establish, maintain, terminate)
4TransportSegmentTCP, UDP — end-to-end delivery
3NetworkPacketIP addressing, Routing
2Data LinkFrameMAC addresses, Ethernet, VLAN, Switches
1PhysicalBitsCables, fiber, radio signals, connectors

🔍7. OSI Layers — Deep Dive

● Layer 1 — Physical

Deals with the transmission of raw bits/signals over a physical medium. No intelligence — just signals.

  • Ethernet cable (copper), Fiber optic cable, Radio signals (Wi-Fi)
  • Electrical signals, Optical signals, Connectors, Pin layouts
  • Devices: Hubs, Repeaters, NICs, Cables, Antennas
PC ───── Ethernet Cable ───── Switch (Layer 1 physical medium)

● Layer 2 — Data Link

Handles frames and MAC addresses. Responsible for node-to-node delivery on the same network.

  • MAC address — unique hardware address of a network interface
  • Ethernet — dominant wired LAN protocol
  • VLAN — logically segmenting a physical network
  • Devices: Switches, Bridges
💡
Example MAC address: A4:5E:60:12:AB:91 — 48 bits, written as 6 hex pairs. MAC → Layer 2.

● Layer 3 — Network

Handles IP addressing and routing. Responsible for end-to-end delivery across multiple networks.

  • IPv4 — 32-bit, e.g. 192.168.1.10
  • IPv6 — 128-bit, next-generation
  • Routing — choosing the best path using routing tables
  • Devices: Routers, Layer-3 Switches
💡
IP address → Layer 3. This is critical — MAC is Layer 2, IP is Layer 3. Interviewers love this question.

● Layer 4 — Transport

Provides end-to-end transport mechanisms between applications on different hosts.

🔓
TCP
Reliable, connection-oriented. Uses 3-way handshake (SYN → SYN-ACK → ACK).
Used by: HTTPS, SSH, HTTP
⚡
UDP
Connectionless, fast, no guarantee. Lower overhead.
Used by: DNS, DHCP, video streaming, gaming
🎓
TCP / UDP → Layer 4. TCP = reliable (slower). UDP = fast (no guarantee). A few lost video frames is better than buffering — that's why video uses UDP.

● Layer 5 — Session

Establishes, manages, and terminates communication sessions. In modern TCP/IP networking, these functions are usually handled by applications rather than a separate layer. For interviews: understand its conceptual role.

● Layer 6 — Presentation

Concerned with how data is represented — formatting, encoding, encryption/decryption, compression. In modern networks these are implemented by specific protocols (e.g., TLS for encryption).

● Layer 7 — Application

The layer closest to end users and applications. Where application protocols live.

  • HTTP / HTTPS — web browsing
  • DNS — name resolution
  • SSH — secure remote access
  • SMTP — email sending
  • FTP — file transfer
🎓
Application protocols → Layer 7.

👥8. TCP/IP Model

The TCP/IP model is the practical protocol architecture behind the Internet. It uses 4 layers.

TCP/IP LayerMaps to OSIKey Protocols
ApplicationLayers 7 + 6 + 5HTTP, HTTPS, DNS, SSH, SMTP, FTP
TransportLayer 4TCP, UDP
InternetLayer 3IP, ICMP, ARP
Network AccessLayers 2 + 1Ethernet, Wi-Fi, MAC
📌
Key insight: OSI is a conceptual reference model. TCP/IP is the practical networking architecture used by the Internet. Don't over-memorize the mapping — understand the main idea.

🔗9. MAC Address

MAC = Media Access Control

A MAC address identifies a network interface at the Data Link layer (Layer 2). It is assigned to the physical hardware (NIC) by the manufacturer.

A4:5E:60:12:AB:91 A4 : 5E : 60 : 12 : AB : 91 │─────────────┐ │─────────────┐ OUI (vendor) Device ID 6 pairs × 8 bits = 48 bits total Written in hexadecimal
🎓
Critical to remember:
MAC → Layer 2 (Data Link) → used by Switches
IP    → Layer 3 (Network) → used by Routers

🌎10. IP Address & Subnet Mask

IPv4 Address

An IP address identifies a network interface at Layer 3. IPv4 uses 32 bits written as 4 octets.

192 . 168 . 1 . 10 ↑ ↑ ↑ ↑ Oct1 Oct2 Oct3 Oct4 Each octet = 8 bits Range per octet: 0 – 255 Total: 4 × 8 = 32 bits

Subnet Mask

A subnet mask determines which part of the IP address is the network and which part is the host.

IP Address: 192.168.1.10 Subnet Mask: 255.255.255.0 CIDR notation: 192.168.1.10/24 ↑ /24 = 24 network bits
📌
Subnetting will be studied in full detail on Day 2. Today just understand what subnet masks are for.

🔓11. Private & Public IP Addresses

Private IPv4 Ranges (RFC 1918)

These are used inside private networks (home, office, cloud VPC). They are not routable on the public Internet.

RangeCIDRExampleTypical Use
10.x.x.x10.0.0.0/810.10.1.20Large enterprise, cloud VPCs
172.16–31.x.x172.16.0.0/12172.20.5.10Medium networks
192.168.x.x192.168.0.0/16192.168.1.50Home/small office

Public IP Address

A public IP is globally routable on the Internet. Your ISP assigns one to your router.

Private Network (192.168.x.x) │ ▼ Router/NAT ← translates private → public │ ▼ Public Internet (e.g. 203.0.113.10)
🎓
Cloud relevance: In AWS/Azure, instances in a VPC use private IPs. They need a NAT Gateway or Elastic IP (public) to reach the Internet.

🚗12. Default Gateway

The default gateway is the router/interface a host sends traffic to when the destination is outside its local subnet.

PC 192.168.1.10 │ ▼ Switch │ ▼ Router (Default Gateway) 192.168.1.1 │ ▼ Internet

A PC's full network configuration looks like:

IP Address: 192.168.1.10 Subnet Mask: 255.255.255.0 Default Gateway: 192.168.1.1 DNS Server: 8.8.8.8
🎓
Important interview point:
A default gateway is NOT required to communicate with hosts on the same subnet.
It IS required to communicate with hosts on different subnets (including the Internet).

📜13. DNS & DHCP

DNS — Domain Name System

DNS translates human-readable domain names into IP addresses. Without DNS, you'd have to remember IP addresses for every website.

You type: google.com ↓ DNS Query ↓ DNS Server resolves to: 142.250.195.46 ↓ Your browser connects to that IP

Common DNS Record Types (study later):

RecordPurpose
AMaps domain → IPv4 address
AAAAMaps domain → IPv6 address
CNAMEAlias — maps one domain to another
MXMail server for the domain
NSName servers for the domain
TXTArbitrary text (used for verification, SPF)

DHCP — Dynamic Host Configuration Protocol

DHCP automatically assigns network configuration to devices so you don't have to configure each one manually.

DHCP provides:

  • IP address
  • Subnet mask
  • Default gateway
  • DNS server
💡
DORA — The 4-step DHCP process:
Discover → Offer → Request → Acknowledgment
The client broadcasts Discover → Server offers an IP → Client requests it → Server confirms.
⚡
Protocol note: Both DNS and DHCP commonly use UDP (Layer 4). DNS uses port 53, DHCP uses ports 67/68.

💻15. Ping & Windows Commands

Ping

ping uses ICMP Echo messages to test IP-level reachability.

ping 8.8.8.8 Reply from 8.8.8.8: bytes=32 time=15ms TTL=118 ↑ Host responded to ICMP Echo request
🎓
Critical interview point: Ping failing does NOT always mean the destination is down. A firewall may be blocking ICMP. Always verify with other methods.

Loopback Address

IPv4 loopback: 127.0.0.1 — tests your local TCP/IP stack without any network communication.

ping 127.0.0.1 → Tests local TCP/IP stack (no network needed) → If this fails, your TCP/IP stack has a problem

Essential Windows Commands

CommandWhat it does
ipconfigShows basic IP configuration (IP, mask, gateway)
ipconfig /allFull details — MAC, DHCP server, DNS servers, lease info
ping 192.168.1.1Tests connectivity to a host using ICMP
tracert google.comTraces the path (hop-by-hop) to a destination
nslookup google.comQueries DNS — shows resolved IP for a domain
arp -aShows ARP cache (IP-to-MAC mappings on your LAN)
netstatShows active network connections and listening ports

🔧16. Basic Troubleshooting Method

When a user says "Internet is not working" — use a structured approach, not random fixes.

🔎
Step 1: Understand the problem — ask questions, reproduce it
📶
Step 2: Check physical / Wi-Fi connection
💻
Step 3: Run ipconfig /all — check IP, mask, gateway, DNS
⚡
Step 4: ping 127.0.0.1 — test local TCP/IP stack
📡
Step 5: ping <default-gateway> — test LAN connectivity
🌐
Step 6: ping 8.8.8.8 — test Internet connectivity (bypasses DNS)
📜
Step 7: nslookup google.com — test DNS resolution
🌐
Step 8: Test the actual application/website in browser
🔧
Step 9: Identify root cause and fix it
✅
Step 10: Verify the fix works
📄
Step 11: Document what you found and fixed

📝 Troubleshooting Example

User says: "Wi-Fi is connected but Google isn't opening."

Ping gateway → SUCCESS ✓ (LAN is fine) Ping 8.8.8.8 → SUCCESS ✓ (Internet is reachable) nslookup → FAIL ✗ (DNS not resolving) Diagnosis: DNS issue — not a network connectivity problem. Fix: Change DNS server to 8.8.8.8 or check DNS server config.
🎓
This troubleshooting mindset — logical, step-by-step isolation — is one of the most valuable skills in cloud networking. Interviewers test this heavily.

🔫Day 1 Practical Lab

Open Windows Command Prompt and run the following commands. Record your results.

1

Run ipconfig /all

ipconfig /all

Identify and note down: IPv4 Address, Subnet Mask, Default Gateway, DNS Servers, MAC address (Physical Address)

2

Test local TCP/IP stack

ping 127.0.0.1

Expected: 4 replies. Confirms your TCP/IP stack is working.

3

Test LAN connectivity — ping your default gateway

ping <your-default-gateway> Example: ping 192.168.1.1

Expected: replies from your router. Confirms LAN is working.

4

Test Internet connectivity

ping 8.8.8.8

Google's DNS server. Success = you have Internet connectivity.

5

Test DNS resolution

nslookup google.com

Shows the IP address that DNS resolved for google.com. Success = DNS is working.
