🌎1. What is IPv4?

IPv4 = Internet Protocol version 4

IPv4 is an addressing system used to identify interfaces on an IP network. An IPv4 address contains 32 bits, divided into 4 octets.

192 . 168 . 1 . 10 ↑ ↑ ↑ ↑ 8 bits 8 bits 8 bits 8 bits 8 + 8 + 8 + 8 = 32 bits total
💡
Every device on an IP network needs a unique IPv4 address to communicate. In cloud (AWS, Azure, GCP), every virtual machine, container and subnet gets an IP address.

📋5. IPv4 Address Structure

An IPv4 address has two logical parts:

NETWORK PORTION | HOST PORTION
Example: 192.168.1.10/24 192.168.1 | 10 NETWORK | HOST /24 → first 24 bits = network last 8 bits = host (32 - 24 = 8)
🎓
The prefix length (e.g. /24) tells you exactly how many bits are the network part. The rest are the host part. This is the foundation of all subnetting.

🏔6. Subnet Mask

A subnet mask identifies which bits of an IPv4 address belong to the network portion and which belong to the host portion.

IP Address: 192.168.1.10 Subnet Mask: 255.255.255.0 Binary subnet mask: 11111111.11111111.11111111.00000000 <——————— NETWORK ————————><— HOST —> The 1s = NETWORK bits The 0s = HOST bits
💡
Notice: 255 in binary = 11111111 (all 1s = all network bits). 0 in binary = 00000000 (all 0s = all host bits). This is why /24 = 255.255.255.0.

📈7. CIDR Notation

CIDR = Classless Inter-Domain Routing

CIDR notation represents the number of network bits using a slash after the IP address.

192.168.1.10/24 ↑ /24 = 24 network bits 8 host bits (32-24=8)
🎓
CIDR replaces the old "classful" system (Class A/B/C). Modern networking — and all cloud platforms — use CIDR exclusively. Always think in CIDR.

🔒9. Network Bits vs Host Bits

192.168.1.10/24 Network portion: 192.168.1 (24 bits) Host portion: 10 (8 bits) 192.168.1 | 10 NETWORK | HOST (identifies (identifies a the subnet) device in that subnet)
💡
All devices in the same subnet share the same network portion. Only the host portion differs. E.g. 192.168.1.10 and 192.168.1.20 are in the same /24 subnet.

🏠10. Network Address

The network address is the first address in a subnet. All host bits are set to 0. It identifies the subnet itself — it cannot be assigned to a host.

IP: 192.168.1.10/24 Network: 192.168.1.0 ← host bits all zero ↑ this is 0, not 10
🎓
The network address = cannot be used as a host address. This is one of the "2" subtracted in the formula 2^n - 2.

📡11. Broadcast Address

The broadcast address is the last address in a subnet. All host bits are set to 1. It cannot be assigned to a host.

Subnet: 192.168.1.0/24 Network: 192.168.1.0 ← first (host bits = 0) Broadcast: 192.168.1.255 ← last (host bits = all 1s = 255)
🎓
The broadcast address = cannot be used as a host address. This is the second "1" subtracted in 2^n - 2.

👥12. Usable Host Range

The usable hosts are all addresses between the network address and the broadcast address.

Subnet: 192.168.1.0/24 Network: 192.168.1.0 ✗ (cannot use) First usable: 192.168.1.1 ✓ Last usable: 192.168.1.254 ✓ Broadcast: 192.168.1.255 ✗ (cannot use) Usable range: 192.168.1.1 – 192.168.1.254

🧮13. Host Calculation Formula

Usable hosts = 2host bits − 2
Subtract 2 for the Network Address and the Broadcast Address
💡
Steps:
1. Find host bits = 32 − prefix length
2. Calculate 2^(host bits)
3. Subtract 2

🏛16. What is Subnetting?

Subnetting means dividing a larger IP network into smaller sub-networks (subnets).

Original: 192.168.1.0/24 (one network) Subnetted into four /26 subnets: 192.168.1.0/26 → hosts .1 – .62 192.168.1.64/26 → hosts .65 – .126 192.168.1.128/26 → hosts .129– .190 192.168.1.192/26 → hosts .193– .254

🤔17. Why Do We Use Subnetting?

🏢
Organisation
Separate departments — IT, HR, Finance, Servers, Guest
🔒
Security
Segmentation controls traffic between groups (firewall between subnets)
📈
IP Management
Use address space efficiently — give each group only what it needs
☁
Cloud VPC
AWS/Azure VPCs are divided into subnets for public, private, DB tiers
🎓
Cloud example: An AWS VPC 10.0.0.0/16 is typically divided into:
Public subnet (10.0.1.0/24) → web servers
Private subnet (10.0.2.0/24) → app servers
DB subnet (10.0.3.0/24) → databases

☁20. Cloud Networking Connection

Subnetting is the foundation of cloud networking. Every AWS VPC, Azure VNet, and GCP VPC uses subnetting directly.

AWS VPC: 10.0.0.0/16 │ ┌─────────┼─────────┐ │ │ │ Public Private DB 10.0.1.0 10.0.2.0 10.0.3.0 /24 /24 /24 Traffic between subnets → controlled by Route Tables + Security Groups

Subnetting → Routing → AWS VPC → Cloud Networking → Cloud Security
